# 风险路由

在执行项目前选择一条路线。项目规则要求更严格时，始终采用更严格要求。

## `readonly`

用于检查、审核、比较、解释或先出方案。

- 不修改项目文件、配置、数据或工作流。
- 不安装依赖，不运行会写入项目的测试/构建，不执行上传或发布。
- `start` 和后续证据必须写在项目外。
- 结束时证明项目 Git 状态与开始基线一致。

## `simple`

必须同时满足：

- 目标和允许范围明确；
- 只涉及少量本地文件；
- 容易回退；
- 不涉及数据口径、安全、隐私、凭据、费用、依赖、共享契约、云端或发布；
- 不存在与用户原有改动的重叠。

至少完成针对性检查、范围检查和证据交付。不要机械运行与改动无关的完整测试。

## `full`

出现以下任一情况时使用：

- 官方数据、解析器、生成物、迁移或历史修订；
- 密钥、权限、隐私、安全、费用或外部账号；
- 安装/升级依赖、共享核心、跨模块或跨平台契约；
- 大范围界面结构、关键交互或多端兼容；
- 云端写入、上传、审核、发布、回滚或删除；
- 修改范围不清、已有改动重叠或失败难以恢复。

按适用范围逐层验证：静态检查 -> 单元/数据测试 -> 构建 -> 实际启动 -> 浏览器/开发者工具 -> 设备 -> 隔离云端 -> 正式平台。不得用前一层推断后一层。

## 必须询问

- 需要扩大允许范围。
- 两种方案会产生明显不同的产品结果。
- 删除、覆盖、付费、发布、生产写入或不可恢复操作未获明确授权。
- 缺少权限、账号或关键产品选择，继续会产生明显风险。

普通命令失败、可诊断环境问题和不改变目标的替代实现由 Codex 自动处理。
