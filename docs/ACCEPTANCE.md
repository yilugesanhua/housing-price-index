# 当前产品验收基线

以下项目按适用平台全部满足后，当前版本才可标记为工程验收完成。每一条必须使用 `[共同]`、`[Web]` 或 `[小程序]` 明确范围；不得再用“未标平台即同时约束两端”的推断。源码版本、历史证据或本地测试不能替代微信开发者工具、双真机、微信审核、正式域名或其他明确列出的外部验收。当前未实现能力只能进入候选或实施差距登记，不能放进当前平台的已通过验收项。

## 状态和证据分层

- `approved` 只表示方案获准；`implemented` 只表示源码或工作流存在；`passed` 必须绑定对应测试和输入；`deployed` 必须绑定目标环境回读；`released` 必须绑定平台发布记录；`stable_archive` 必须绑定只读归档和版本身份。任何状态缺少对应证据时必须降级为 `partial` 或 `not_verified`。
- 设计讨论、历史快照、旧截图、旧运行 ID 和本地模拟只能作为绑定日期的历史证据，不能关闭当前实现、云端、微信平台或真机验收项。
- 每个跨系统对象必须同时记录唯一身份、字段语义、提交 SHA、运行 ID/attempt、目标环境和验证时间；恢复、重跑和收尾使用新身份并追加证据，不得覆盖原始批准意图。
- 验收失败必须证明安全行为：保留旧版本或旧指针、拒绝候选或停止写入。不能以测试通过替代错误数据阻断、权限拒绝、云端回读或平台现场核验。
