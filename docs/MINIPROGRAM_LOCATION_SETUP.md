# 小程序自动定位配置

当前小程序首页定位入口使用 `scope.userFuzzyLocation` / `wx.getFuzzyLocation` 获取模糊位置，再通过云函数和腾讯位置服务逆地理编码为省、市并匹配70城；不使用 `wx.getLocation` 精确定位。未配置云环境或定位失败时，用户仍可点击城市名称手动选择。

## 控制台配置

1. 在腾讯位置服务控制台创建应用和 WebService API Key，并启用逆地址解析。
2. 在微信开发者工具中为当前小程序创建或选择云开发环境。
3. 将云环境 ID 写入 `apps/miniprogram/config/location.js` 的 `cloudEnvId`。
4. 在云函数 `reverseGeocode` 的环境变量中新增 `TENCENT_LBS_KEY`。不要将 Key 写入代码、提交到仓库或发送到聊天中。
5. 在微信开发者工具中右键 `cloudfunctions/reverseGeocode`，选择“上传并部署：云端安装依赖”。该函数没有第三方依赖。
6. 确认 `apps/miniprogram/app.json` 声明 `scope.userFuzzyLocation` 和 `getFuzzyLocation`。正式关闭定位披露问题前，来源页、该授权说明和微信公众平台用户隐私保护指引必须统一如实说明：模糊位置经项目云函数提交腾讯位置服务，仅用于解析省市和匹配城市；项目业务代码不持久化经纬度，但会在本机保存匹配后的 `cityId` 和 `locatedAt`。
7. 在Android微信和iPhone微信分别完成首次授权、拒绝授权、24小时缓存使用边界、过期记录清理、手动选城后重启、分享路由打开和点击图标重新定位测试；没有真机证据时不得把定位验收标记为通过。

## 运行规则

- 分享路由中的 `focus` 优先，不会被自动定位覆盖。没有分享路由时先恢复本地状态；历史来源标记为手动选择时不再自动覆盖，否则尝试使用定位缓存或发起模糊定位。没有可用状态时默认北京并继续尝试定位。
- 自动定位匹配结果通过本地键 `housing-location-cache-v1` 保存 `cityId` 和 `locatedAt`，最长保留24小时。启动恢复和点击定位两条读取路径发现记录过期、时间在未来、城市无效或结构无效时立即删除；期限内启动可复用，用户主动点击定位图标时重新定位，成功后覆盖原记录。
- 精确匹配70城时使用该城市。非70城时，同省70城样本仅一城则使用该城；有多城时优先省会；没有同省样本时保留当前城市并提示手动选择。
- 自动定位成功会把趋势城市重置为定位城市。用户手动选择当前城市时，趋势列表不足三座才追加该城市；已满时只切换当前城市。
- 定位失败、用户拒绝授权、云函数或腾讯位置服务不可用时保留当前城市，并允许手动选择。

## 位置数据边界

- 小程序把 `wx.getFuzzyLocation` 返回的模糊经纬度发送给 `reverseGeocode` 云函数；云函数调用腾讯位置服务后只向小程序返回省、市。
- 当前项目业务代码不持久化经纬度；定位缓存只保存匹配后的 `cityId` 和 `locatedAt`，其他本地状态另行保存当前筛选和来源标记。当前 `v2.4.1` 本地候选在读取时删除超过24小时或无效的定位记录；来源页确认“清除本地记录”后同时删除筛选、来源标记和定位缓存。平台及腾讯位置服务侧的数据处理仍须以实际账号配置和隐私规则为准。
- Web不调用定位接口，继续使用“重点城市”选择器。

## 当前披露阻断

当前 `v2.4.1` 本地候选的来源页和 `apps/miniprogram/app.json` 已明确披露模糊位置信息、项目云函数、腾讯位置服务、不持久化经纬度及本机 `cityId`/`locatedAt` 最长24小时，缓存代码也已实现过期/无效记录删除。上述结论只来自本地源码与定向测试；微信公众平台隐私保护指引无法现场核验，Android/iPhone真机显示和平台存储行为未验证。I11保持 `partial/passed_limited`，只有平台披露逐项一致且双真机证据可回读后才能关闭。

## 凭据安全

`TENCENT_LBS_KEY` 只存在于云函数环境变量。小程序包和云函数源码都不得包含真实 Key。腾讯位置服务控制台还应为 Key 设置可用服务和调用配额限制。
